## Inventory pribadi (migrasi 0017–0018)

- **Model.** `inventory_items` hanya menyimpan URL (8–2048 karakter, wajib diawali `https://`; tidak ada validasi host atau port), `owner_id`, `class_id`, dan waktu. `inventory_keys` menyimpan `token` 16 karakter (unik global, kapital), `ttl` (`24h`, `7d`, `1m`, `6m`, `never`), `expires_at`, dan `revoked_at`. Keduanya terikat pada baris `memberships` dengan `on delete cascade`.
- **Akses.** RLS: pemilik aktif hanya melihat dan menulis itemnya sendiri; tabel key tidak punya policy tulis sama sekali. Pembuatan dan pencabutan key hanya lewat RPC `security definer` (`create_inventory_key`, `revoke_inventory_key`), jadi kuota dan format tidak bisa dilewati lewat PostgREST.
- **Kuota.** Maksimal 12 key **aktif bersamaan** per anggota. Pemeriksaan hanya menghitung key yang belum dicabut dan belum kedaluwarsa, serta mengunci baris keanggotaan pemilik agar dua permintaan bersamaan tidak lolos batas (error `EC070`). Mencabut key atau membiarkannya kedaluwarsa mengosongkan satu slot; riwayat key lama tetap disimpan. Migrasi 0018 mengoreksi 0017 yang sempat menghitung semua baris.
- **Key.** Pemilik memilih key custom 16 karakter (huruf, angka, `-`, `_`; disimpan kapital) atau membiarkannya kosong untuk key acak 16 karakter dari 32 simbol tanpa `0/O/1/I/L` (80 bit dari `gen_random_uuid`). Format salah `EC072`; token bentrok `23505`.
- **Mati otomatis.** `get_inventory_by_key` hanya mengembalikan baris bila key tidak dicabut, belum kedaluwarsa, dan pemiliknya anggota aktif. Key mati, salah format, atau tidak ada semuanya menghasilkan nol baris tanpa membedakan penyebabnya. Nama pemilik hanya ikut bila `page.members` terlihat oleh pemanggil.
- **Halaman publik.** `/inventory/access` tidak memerlukan login. Key dikirim lewat Server Action (POST) dan tidak pernah masuk URL, riwayat, atau cache halaman. `/inventory` sendiri memerlukan login anggota aktif.
- **Batas baca.** Lookup mengembalikan maksimal 500 item terbaru milik satu pemilik. Belum ada rate limit untuk percobaan key; ruang key acak 80 bit membuat tebakan tidak praktis, tetapi key custom yang mudah ditebak bergantung pada pilihan pemilik.
- **Navigasi.** Anggota aktif melihat **Inventory** di sidebar/menu, halaman masuk menautkan `/inventory/access` untuk perangkat lain, dan beranda publik menampilkan tombol **Akses inventory** untuk tamu.

## QR Studio (migrasi 0019)

- **Halaman publik.** `/qr` dapat dibuka tanpa login. Tautan **QR Studio** selalu ada di navigasi utama, baik untuk tamu maupun anggota; tamu juga melihat tombol **Buat QR** di hero beranda dan kartu **QR Studio** di blok jelajah. Pembuatan matriks dan gambar terjadi di browser; server hanya memvalidasi dan menyimpan PNG.
- **Dua mode.** **Normal** memakai modul kotak standar. **Custom** menyalin alur skrip referensi Python `qr_custom.py` dan `qr_custom-add_direction_dots.py` (salinan referensinya tidak lagi disertakan di repo): bentuk titik kotak/bulat/balok (finder pattern membulat), warna QR dan latar, serta ikon tengah opsional dengan bentuk border kotak/rounded/bulat/segitiga/outline, mode crop/shrink, gap, ketebalan 1–100, dan warna border. Balok punya empat orientasi: **horizontal** (bawaan, keluaran lama tidak berubah), **vertikal**, **diagonal turun**, dan **diagonal naik**; semuanya memakai ujung membulat dan panjang beragam seperti bawaan skrip. Preset warna dan nilai bawaannya sama dengan skrip (biru `#4da3d9` di atas putih).
- **Paritas render.** Parameter sama: koreksi galat **H**, versi otomatis, `box_size=12`, `border=4`, padding titik 12%, balok 55%, ikon 23% lebar QR, ketebalan border 50% jari-jari bentuk, dan dilasi outline memakai transformasi jarak Euclidean. Matriks memakai `qrcode` npm 1.5.4. Untuk `https://example.com`, matriks dan gambar kotak identik piksel dengan keluaran Python; bulat 93,8% dan balok 98,3% identik pada ambang selisih >16, ikon 99,8%+. Empat orientasi balok diuji terpisah terhadap `qr_custom-add_direction_dots.py` (rounded + varied): horizontal 97,55% identik/98,30% ambang 16, vertikal 97,42/98,22, diagonal turun 91,02/95,30, diagonal naik 90,92/95,29. Perbedaan tersisa berasal dari antialias tepi dan pemilihan mask Python yang berbeda untuk sebagian teks non-URL (bug pemilihan mask di `qrcode` Python 8.2); QR tetap valid.
- **Penyimpanan.** Bucket publik `qr-shares` (migrasi 0019), batas 4 MiB, hanya `image/png`. Nama objek UUID acak. Tidak ada policy daftar/tulis/hapus untuk anon/authenticated; unggah dan hapus memakai service role di `src/lib/qr/server.ts`. Tes 008 memastikan anon tidak bisa mendaftar, mengunggah, atau menghapus objek.
- **Unggah.** `POST /api/qr` menerima multipart, memeriksa magic bytes PNG, dimensi persegi yang harus tepat `(modul + 8) × 12` dengan modul 21–177 (versi 1–40, 348–2220 px), dan ukuran ≤4 MB. Rate limit best-effort 8 unggahan per 10 menit per IP (per proses; bukan batas keras di serverless). Respons berisi URL publik, URL unduh (`?download=`), dan `expiresAt` 6 jam.
- **Pembersihan.** Objek lebih tua dari 6 jam dihapus lewat Storage API sebelum unggahan baru, saat halaman `/qr` dibuka (POST `/api/qr/cleanup`), dan pada cron harian `/api/health`. Endpoint pembersih publik hanya menghapus objek kedaluwarsa dan dibatasi 6 permintaan per 10 menit per IP; pemanggil dengan `Bearer CRON_SECRET` melewati batas itu. **Batasan:** tidak ada penjadwal per jam, jadi bila situs sama sekali tidak dibuka dan cron harian belum berjalan, file bisa melewati 6 jam sampai aktivitas berikutnya. Cache CDN objek juga dapat menyajikan salinan hingga 1 jam setelah penghapusan.
- **Keterbacaan.** UI memperingatkan kontras <4,5:1 dan menyarankan warna hitam. `jsQR` berhasil membaca QR normal hitam, tetapi tidak membaca QR biru bawaan skrip maupun bentuk bulat/balok; keluaran Python referensi juga gagal di `jsQR`, jadi ini sifat gaya tersebut, bukan regresi renderer. Pemindaian dengan kamera ponsel sungguhan belum diuji.
- **Unduhan.** Kartu hasil menampilkan URL gambar, tombol **Salin tautan**, tombol **Unduh PNG** (query `download`), dan tautan buka gambar. Pesan menyebut tautan aktif sampai waktu kedaluwarsa dan file dihapus setelah 6 jam.

## Portofolio: pratinjau tautan

- **Urutan gambar kartu:** gambar unggahan anggota → `og:image` tautan → kotak pengganti berisi origin tautan (mis. `https://www.myeclipse.my.id`). Metadata dibaca `src/lib/preview/meta.ts` (murni, diuji unit) dan diambil `src/lib/preview/server.ts` di server dengan cache data Next 24 jam (tanpa perubahan skema). Pratinjau hanya diambil untuk item yang gambarnya memang tidak tersedia — belum diunggah, atau objek Storage-nya gagal ditandatangani — jadi gambar unggahan tidak pernah tertimpa oleh pratinjau.
- **Batas pengambilan.** Hanya https tanpa kredensial di port 443, host berdomain, dan alamat hasil resolusi DNS harus publik; pengalihan diikuti manual maksimal tiga kali dengan pemeriksaan ulang setiap tujuan, badan dibaca maksimal 200 KB, timeout 4 detik, dan hanya `content-type` HTML yang diterima. Maksimal 12 tautan per render dengan 6 permintaan paralel dan anggaran waktu 5 detik per render (batch berikutnya hanya dimulai bila masih muat); kegagalan di-cache 10 menit di memori proses supaya render berikutnya tidak menunggu timeout lagi.
- **Perlakuan alamat IPv6 ULA.** Alamat `fc00::/7` diabaikan bila host juga punya IPv4 publik, karena resolver NAT64/DNS64 (umum di jaringan seluler dan sandbox pengembangan ini) memetakan host publik ke `fd00::/8`; menolaknya membuat fitur ini mati total. Literal IP internal, loopback, dan link-local tetap selalu ditolak, dan host yang hanya punya IPv6 diperiksa apa adanya. **Sisa risiko:** DNS yang dengan sengaja mengembalikan IPv4 publik bersama IPv6 internal belum tertutup.
- **Gambar di-hotlink** dari host situs sumber dengan `referrerPolicy="no-referrer"`. Konsekuensinya CSP rute terkait membuka `img-src https:` dan IP pembaca terlihat oleh host itu. Gambar bersifat dekoratif (`alt=""`); lapisan pengganti di bawahnya tetap terlihat bila host menolak hotlink.
- **Label situs** (`og:site_name`/`application-name`, jatuh ke host tautan) hanya tampil sebagai lencana di atas gambar. Tanpa gambar, kotak pengganti menampilkan origin tautan sehingga kartu tetap tidak kosong walau pengambilan gagal.
- **Daftar `/settings/portfolio`** menampilkan thumbnail (gambar unggahan sendiri, selain itu gambar pratinjau) dan label situs di baris meta. Item yang sudah punya gambar unggahan tidak menembak situs luar sama sekali.
- **Kartu di profil publik adalah tautannya sendiri.** Judul dibungkus `<a class="stretch" target="_blank" rel="noopener noreferrer">` dan lapisan `::after`-nya menutup seluruh kartu, jadi klik di area gambar maupun teks membuka tautan di tab baru tanpa tautan bersarang. Teks "Lihat karya" hanya penunjuk visual; pembaca layar mendengar "(dibuka di tab baru)". Item tanpa `url` tidak punya lapisan itu.
- **Tinggi kartu konstan.** Media tetap 16:9, judul dipangkas dua baris, deskripsi tiga baris (`.clamp-2`/`.clamp-3`), dan kartu mengisi tinggi baris grid. Teks yang terpotong memunculkan tombol **Baca selengkapnya** (`src/components/portfolio-text.tsx`) yang membuka `<dialog>` berisi teks utuh. Pengukuran di klien: kelas pangkas dilepas sesaat lalu `scrollHeight` dibaca dan kelasnya dipasang lagi, diulang saat jendela berubah ukuran. Tombol itu memakai `.above` agar tetap bisa diklik di atas lapisan tautan kartu.

## Keamanan

- `src/proxy.ts` (Next 16): CSP per-permintaan dengan nonce (`lib/security/csp.ts`), diteruskan ke layout lewat header `x-nonce`, dibangun ulang setelah refresh cookie. - `next.config.ts`: X-Content-Type-Options, Referrer-Policy, X-Frame-Options DENY, Permissions-Policy, COOP same-origin. HSTS diserahkan ke Vercel.
- Cookie sesi Supabase diberi `httpOnly`, `sameSite=lax`, `secure` (produksi), `path=/` di `proxy.ts` dan `lib/supabase/server.ts`.
- Admin client hanya untuk Auth Admin API; semua baca/tulis konten memakai JWT pengguna di bawah RLS.
- Knowledge menegakkan akses di database: RLS pada semua tabel, RPC `security definer` dengan pemeriksaan eksplisit, trigger guard untuk kolom konten/visibilitas/status, dan grant kolom minimum. Tidak ada tabel Knowledge yang bisa ditulis langsung lewat PostgREST kecuali entri (dengan guard) — tabel permintaan/editor/audit hanya lewat RPC.
- Email OTP perubahan email disimpan di `public.email_change_requests` sebagai HMAC-SHA256 (kunci `SUPABASE_SECRET_KEY`), terikat ke user + alamat tujuan. Tabel tanpa grant/policy untuk anon/authenticated; hanya service role dari Server Action. Verifikasi memakai perbandingan waktu-tetap, maksimal 5 percobaan, dan baris dihapus sebelum email Auth diubah.
- Masuk dengan Google memakai Google Identity Services, bukan redirect OAuth: skrip `accounts.google.com/gsi/client` hanya dimuat di `/login` (CSP `allowsGoogleSignIn`), dan ID token ditukar di server lewat `signInWithIdToken` dengan klien `@supabase/ssr`, sehingga cookie sesi tetap ditulis server seperti login kata sandi. Nonce acak 32 byte disimpan di cookie httpOnly `gsi_nonce` (10 menit, sekali pakai, `sameSite=lax`); Google menerima SHA-256 hex-nya dan Supabase membandingkannya dengan klaim `nonce`. Sebelum token dikirim, server menolak issuer selain `https://accounts.google.com`, nonce yang tidak cocok, `email_verified` bukan `true`, atau token kedaluwarsa. Setelah sesi ada, sesi diakhiri bila `email_confirmed_at` kosong atau status keanggotaan bukan `active`. Klien Google Secret tidak ada di aplikasi; hanya Client ID publik di `GOOGLE_CLIENT_ID`.
- Tombol Google memakai `renderButton` resmi (bukan tombol kustom) karena GIS hanya mengeluarkan ID token lewat tombol resmi atau One Tap; pop-up-nya membutuhkan `Cross-Origin-Opener-Policy: same-origin-allow-popups` di `next.config.ts` (sebelumnya `same-origin`). Otomatis penautan Supabase menautkan identitas Google ke akun kata sandi dengan email terverifikasi yang sama, sehingga tidak ada akun duplikat; akun Google yang belum menjadi anggota ditolak.
- `supabase/config.toml`: `enable_signup=false` (lokal), sandi minimal 10, OTP 24 jam, hanya schema `public` yang diekspos, batas bucket 2 MiB. **Pengaturan ini hanya berlaku lokal.** Di proyek cloud, matikan "Allow new users to sign up" (agar akun Google asing ditolak `signup_disabled` sebelum baris `auth.users` dibuat), aktifkan provider Google, isi Site URL `APP_URL`, dan tambahkan `APP_URL` sebagai *authorized JavaScript origin* di Google Cloud Console.

## Google Drive Uploader (migrasi 0021)

- **Alur.** `/cloud` hanya untuk anggota aktif. Server membuat sesi resumable Google Drive, lalu peramban mengirim potongan 8 MiB langsung ke `www.googleapis.com`; CSP `connect-src` dibuka hanya di rute itu. Folder: `GDRIVE_ROOT_FOLDER_ID` (wajib), `GDRIVE_PICTURES`, `GDRIVE_VIDEOS`, `GDRIVE_AUDIOS`, `GDRIVE_DOCUMENTS`, `GDRIVE_ARCHIVES_ID`, dan induk folder custom `GDRIVE_CUSTOM`. Kategori yang tidak diset jatuh ke root; kategori yang diset tetapi tidak dapat diakses menghasilkan galat, bukan pengalihan diam-diam. Tidak ada bucket Supabase baru.
- **Tujuan.** Prioritas: pilihan pada unggahan → default pribadi → folder kategori → root. Folder custom dibuat di bawah `GDRIVE_CUSTOM` (atau root). Folder eksternal menerima ID atau link `drive.google.com/drive/folders/...`; link file/dokumen ditolak, lalu metadata, status folder, dan permission `anyone` + `writer` diperiksa, diikuti uji `dummy.txt` (buat, hapus, verifikasi hilang). Kepemilikan folder berasal dari `auth.uid()` di RPC, bukan dari frontend, dan akses folder diperiksa ulang setiap unggahan. Dialog tambah folder punya **penelusuran folder kelas**: server mendaftar maksimum 100 subfolder per tingkat (nama + owner bila tersedia), folder hanya bisa ditelusuri di bawah folder utama kelas (rantai induk maksimal 12 tingkat), dan tombol tambah mendaftarkan subfolder yang sedang dibuka. Tombol hapus hanya muncul untuk folder yang didaftarkan pemanggil sendiri dan hanya melepas catatan Eclipse; isi Drive tidak disentuh.
- **Nama file.** Default `<nama asli> — YYYY-MM-DD HH.MM.SS.<ext>` memakai zona waktu kelas; nama custom mempertahankan ekstensi hasil validasi, menghapus path traversal/karakter berbahaya, dan dibatasi 180 karakter. Benturan nama dihindari dengan ` (2)`, ` (3)`, … setelah pemeriksaan nama di Drive.
- **Validasi.** Allowlist ekstensi, MIME, dan signature (JPEG/PNG/WebP/HEIC, MP4/MKV/MOV, MP3/M4A/AAC/WAV/FLAC, PDF/TXT/MD/DOC/DOCX/XLS/XLSX/PPT/PPTX/ZIP/RAR). MP4/MOV dikenali dari box `ftyp` (termasuk box `free` sebelum `ftyp`) untuk brand apa pun seperti `iso4` dan brand buatan encoder; hanya brand HEIC dan M4A yang dipisahkan, sehingga file MP4 sah tidak ditolak karena brand di luar daftar. Arsip hanya bila Ketua mengizinkan; batas ukuran dari `gdrive_settings` (bawaan 500 MB, dapat diubah Ketua sampai 2048 MB). Metadata file hasil unggahan dibaca dengan field dasar (tanpa `permissions`/`capabilities`, yang hanya diminta untuk folder), karena file yang dibuat di folder milik akun lain bisa dijawab Google sebagai 404 walau file ada. Setelah file ada di Drive, server membaca beberapa KB pertama dan menghapus file bila signature tidak cocok; file kosong dan ekstensi/signature yang tidak konsisten ditolak. `txt`/`md` diverifikasi sebagai teks, bukan biner.
- **Ketahanan.** Sesi dan progres disimpan di `gdrive_uploads` (kedaluwarsa 12 jam). Refresh menutup koneksi browser karena unggahan berjalan langsung dari peramban; pengguna memilih file yang sama lewat **Lanjutkan** untuk meneruskan dari byte terakhir. Respons PUT yang gagal dibaca peramban (CORS, timeout, koneksi putus) tidak dianggap bukti kegagalan: server memeriksa sesi lewat `sessionStatus`, memverifikasi metadata dan signature, lalu mencatat `completed`; bila Drive belum menerima seluruh file, progres diperbarui dan sesi dipertahankan untuk **Lanjutkan**. Pembatalan hanya dijalankan atas permintaan pengguna, didahului pemeriksaan sesi (file yang sudah selesai difinalisasi, bukan dibatalkan), dan DELETE sesi yang gagal dilaporkan sebagai galat tanpa menandai baris `cancelled`. Baris yang terlanjur berakhir padahal Drive sudah menyelesaikan filenya direkonsiliasi menjadi `completed` lewat `reconcile_gdrive_upload` (migrasi 0022). Bila ID file dari sesi tidak terbaca, server mencari file lewat `appProperties` `eclipseUploadId` lalu lewat nama di folder tujuan (ukuran harus sama) sebelum menyimpulkan file hilang; baris yang benar-benar tanpa file ditandai `failed` dengan `error_code` `file_missing` agar pengguna bisa mengunggah ulang tanpa menunggu sesi kedaluwarsa. Pengaturan kelas (ukuran dan arsip) ada di `/settings/cloud` dengan permission `class.manage`.
- **Tampilan.** `/cloud` memakai tata letak dua kolom: kartu unggah (area seret-lepas, daftar berkas terpilih dengan ubah nama per file, pilihan tujuan berbentuk radio bila ≤4 opsi dan select bila lebih, ringkasan di kaki kartu) berdampingan dengan kartu **Tujuan saya** (daftar folder, bintang default, hapus, dialog tambah folder custom/eksternal). Panduan bertab (cara kerja, aturan unggah, urutan tujuan, folder) ada di dialog; unggahan berjalan dan unggahan terhenti tampil dalam kartu **Unggahan** yang sama. Progres memakai `<progress>` native agar tidak memerlukan atribut `style` (CSP nonce).
- **Batasan/risiko.** Sesi resumable dibuat server dengan header `Origin` (dari `APP_URL` ditambah `GDRIVE_UPLOAD_ORIGINS`); origin lain ditolak sebelum sesi dibuat karena tanpa Origin yang cocok respons PUT peramban tidak membawa header CORS. Alur ini belum diuji dengan kredensial Google nyata di sandbox ini. Signature baru diperiksa setelah unggahan selesai, sehingga file berbahaya bisa sempat tersimpan beberapa detik sebelum dihapus. Folder eksternal divalidasi dengan dummy saat ditambahkan, bukan setiap unggahan, tetapi permission-nya diperiksa ulang. Unggahan ke folder eksternal dikirim langsung dengan folder itu sebagai induk sesi resumable, tanpa folder penampung; pengujian lapangan menunjukkan byte benar-benar masuk ke folder eksternal lewat jalur ini, dan menghapus folder penampung juga menghilangkan langkah yang bisa gagal sebelum byte pertama terkirim. Baris lama yang masih berada di folder penampung tetap diselesaikan: file dipindahkan dengan `addParents`/`removeParents` lalu diperiksa. Lokasi file hasil unggahan ditentukan dari `parents` yang dilaporkan Drive (`uploadLocation`), bukan dari menghitung ulang jenis folder. Untuk folder yang dibagikan lewat tautan, `parents` yang tidak terlihat tidak dianggap bukti file salah tempat: log `gdrive verify folder tidak terbaca` mencatat `linkShared` dan baris tetap difinalisasi. Ukuran, status `trashed`, dan folder diperiksa terpisah, dan setiap ketidakcocokan dicatat ke log server (`gdrive verify …` dengan ukuran/folder sebenarnya, tanpa token atau isi file). Metadata yang tidak cocok **tidak lagi menghapus file**: baris unggahan dibiarkan aktif agar verifikasi bisa diulang setelah penyebabnya diketahui. Sesi resumable adalah URL bearer yang diberikan hanya kepada pemilik baris unggahan.
